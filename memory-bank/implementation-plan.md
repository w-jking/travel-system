# 实施计划（面向 AI 开发者的分步指令）

本计划依据 PRD 与技术栈要求编写，优先完成基础系统能力，完整功能放在后续阶段。每一步均包含可验证的测试指令，仅给出清晰的执行说明，不包含任何代码。

## 全局规则与标准（先确认后执行）

- 订单状态集合：待确认、已收款、已出团、已完成、已取消  
- 订单状态跳转：允许在以上状态间按业务需要直接跳转，但必须记录原因  
- 大额订单阈值：订单金额超过 10 万触发审批  
- 退款审批：客户发起退款申请后，需由指定审批角色审核通过才能执行退款  
- 导出审批：导出敏感数据或批量数据必须先提交申请并审核通过  
- 数据脱敏规则：  
  - 手机号：中间四位脱敏  
  - 证件号：除前四位与后两位外全部脱敏  
  - 邮箱：中间四位脱敏  
  - 脱敏字符：统一使用 *  
- 验收口径：接口返回 200 且数据正确，数据状态与流程状态符合业务规则  
- 运行环境：仅本地 Windows  
- 备份策略：每周一次全量备份，保留 15 天；每 7 天执行一次恢复演练  

## 阶段一：基础系统功能（优先完成）

### 步骤 1：建立项目结构与环境基线

- 指令：创建前后端项目骨架，使用本机 Node（Windows）本地运行前后端  
- 指令：安装依赖并分别启动前端与后端本地开发服务  
- 验证测试：在浏览器访问前后端服务，确保返回 200 且页面/接口可用  

本机运行说明（执行级指令）：  
- 前端：进入 frontend 目录，执行依赖安装与启动（本机 Node）  
- 后端：进入 backend 目录，执行依赖安装与启动（本机 Node）  
- 环境：确保本地 PostgreSQL 与 Redis 已启动（参考 .env.example）  

测试验收（必须同时满足）：  
- 打开 http://localhost:3000/health 返回 200 且内容包含 status=ok  
- 打开 http://localhost:5173/ 返回 200 且页面显示“员工与客户管理系统”与“前端服务已启动”  

### 步骤 2：定义核心数据模型清单

- 指令：根据 PRD 梳理员工、客户、订单、回访记录、权限角色、操作日志等基础实体与字段清单  
- 指令：明确每个实体的最小必填字段与可选字段  
- 验证测试：通过评审清单与 PRD 要求逐条对照，确认字段覆盖率  

必填字段（建议）：  
- 员工：姓名、手机号、部门、岗位、角色、状态  
- 客户：姓名、联系方式、客户等级、负责人  
- 订单：客户、订单金额、收款主体、状态、负责人、下单日期  
- 回访记录：客户、回访时间、沟通方式、主要诉求、结果、负责人  

可选字段（建议）：  
- 员工：邮箱、入职日期、工号  
- 客户：证件号、出生日期、旅游偏好、历史订单备注  
- 订单：出团日期、产品线路、备注  
- 回访记录：下次回访时间、附件说明  

### 步骤 3：建立数据库与迁移流程

- 指令：搭建 PostgreSQL 实例并建立迁移流程，确保表结构可持续演进  
- 验证测试：执行一次迁移并回滚，确认可重复执行与无残留且返回 200  

### 步骤 4：完成认证与基础权限框架

- 指令：实现登录、会话、角色与权限基础框架  
- 指令：制定权限矩阵并落实到访问控制  
- 验证测试：用不同角色账号验证访问权限边界是否正确且返回 200  

权限矩阵（建议）：  
- 管理员：员工/客户/订单/日志/导出全权限  
- 部门负责人：本部门员工与客户读写；订单读写；日志读取；导出审批与执行  
- 一线员工：本人负责客户与订单读写；日志仅查看与本人相关；导出需申请  
- 数据管理员：导出审批与执行；日志读取；无业务数据写权限  

页面与功能级权限规则（建议）：  
- 员工管理页：  
  - 列表查看：管理员、部门负责人  
  - 新增/编辑/停用：管理员  
  - 分配角色与权限：管理员  
  - 导入/导出：管理员，部门负责人需审批  
- 客户管理页：  
  - 列表查看：管理员、部门负责人、负责该客户的一线员工  
  - 新增/编辑：管理员、部门负责人、一线员工（仅本人负责客户）  
  - 批量导出：管理员、数据管理员（需审批）  
  - 删除：管理员（需审批）  
- 订单管理页：  
  - 列表查看：管理员、部门负责人、一线员工（仅本人订单）  
  - 创建/编辑：管理员、部门负责人、一线员工（仅本人订单）  
  - 状态变更：管理员、部门负责人、一线员工（需记录原因）  
  - 退款发起：一线员工、部门负责人  
  - 退款审批：管理员、部门负责人  
  - 大额订单审批：管理员、部门负责人  
- 回访记录页：  
  - 查看：管理员、部门负责人、一线员工（仅本人记录）  
  - 新增/编辑：管理员、部门负责人、一线员工（仅本人记录）  
- 日志审计页：  
  - 查看：管理员、部门负责人、数据管理员  
  - 导出：管理员、数据管理员（需审批）  
- 导出审批页：  
  - 申请：一线员工、部门负责人  
  - 审批：管理员、数据管理员  

页面与字段级规则（建议）：  
- 员工详情页：  
  - 必填：姓名、手机号、部门、岗位、角色、状态  
  - 可选：邮箱、入职日期、工号  
  - 展示：手机号脱敏；管理员可查看完整  
- 客户详情页：  
  - 必填：姓名、联系方式、客户等级、负责人  
  - 可选：证件号、出生日期、旅游偏好、历史订单备注  
  - 展示：手机号、证件号、邮箱脱敏；管理员可查看完整  
- 订单详情页：  
  - 必填：客户、订单金额、收款主体、状态、负责人、下单日期  
  - 可选：出团日期、产品线路、备注  
  - 展示：金额与状态必须与流程一致  
- 回访详情页：  
  - 必填：客户、回访时间、沟通方式、主要诉求、结果、负责人  
  - 可选：下次回访时间、附件说明  
  - 展示：仅本人及上级可查看完整内容

## 满足度评估与补齐计划（基于现状自检）

- 已满足的关键项：  
  - 员工、客户、订单、回访基础流程与权限分级  
  - 操作日志与脱敏展示（手机号/证件号/邮箱）  
  - 大额订单与退款审批流（含角色边界与日志留痕）  
  - 导出审批与后端强校验（导出需审批且校验 scope 与发起人）  
  - 异常行为预警（撤单激增、线下收款、非工作时段敏感操作）  
  - 统计报表（员工绩效、客户价值）  
  - 自动备份（每周、保留 15 天）与恢复演练
  - 订单状态下拉固定选项（待确认、已收款、已出团、已完成、已取消）
  - 收款账户配置与订单绑定（非公司账户标记线下并触发预警）
- 未满足或体验不足的项与补齐任务：  
  - 客户/订单负责人需手填 UUID，易错且影响流转体验  
    - 计划：前端改为下拉选择员工（来源 employees/list），并在创建/更新时自动带出当前用户为默认负责人  
  - 异常预警与备份仅有后端接口，缺少前端可视化与操作入口  
    - 计划：前端新增“异常预警”页（列表/处理）与“备份管理”页（查看备份、手动备份、恢复演练）  
  - 导出审批前端仅展示列表，缺少申请/审批操作  
    - 计划：在“导出审批”页加入申请、通过、拒绝按钮，并联动导出入口传递审批编号  
  - 敏感操作二次确认缺失（前端层面）  
    - 计划：对订单取消、退款申请、批量导出等动作增加前端二次确认弹窗，并保留审批与审计
